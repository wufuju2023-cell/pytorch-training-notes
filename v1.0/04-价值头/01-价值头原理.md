## 0. 一页速览

**【注 VH.1.1｜R-VH.1.1】（标量头 vs 64-bin 分类头速览）**

| 概念 | 标量价值头 | 64-bin 分类价值头 |
| --- | --- | --- |
| 输出 | $\hat V \in [-1,1]$（Tanh） | 64 个 logits $z\in\mathbb{R}^{64}$ |
| 解码 | 直接读 $\hat V$ | $p=\mathrm{softmax}(z)$，$\hat d=\sum_k p_k\,k$ |
| 目标 | 折扣回报 / 归一化深度（回归值） | two-hot 分布（相邻两桶按小数部分加权） |
| 损失 | MSE / Huber（proper for mean） | 交叉熵（proper for distribution） |
| 实现 | `Linear(H,256)→SiLU→Linear(256,1)→Tanh` | `Linear(H,256)→SiLU→Linear(256,64)` |
| 优点 | 简单、单值、可直接当 Q 用 | 保留不确定性、桶 64 饱和、天然有界 |
| 代价 | 无分布、对离群目标不稳 | 需要维护桶语义、ECE 更强依赖校准 |

## 1. 价值函数与折扣回报

**【定义 VH.2.1｜D-VH.2.1】（状态价值、动作价值与优势）**

策略 $\pi$ 在状态 $s$ 下的**状态价值**定义为从该状态出发的期望折扣回报：

$$
V^\pi(s)=\mathbb{E}_{\pi}\!\left[G_t \mid S_t=s\right],
\qquad
G_t=\sum_{k=0}^{\infty}\gamma^{k} R_{t+k+1},\quad \gamma\in[0,1].
$$

**动作价值**与**优势**：

$$
Q^\pi(s,a)=\mathbb{E}_{\pi}[G_t\mid S_t=s,A_t=a],
\qquad
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s).
$$

在证明搜索里，$a$ 就是一条 tactic，$R$ 通常只在终止时非零（证明成功 / 失败 /
超步数），因此 $V$ 直接回答："这个中间状态最终能被证出来的概率、或离证出还有多
远"。MCTS 用 $Q$ 排序候选动作，用 $V$ 评估叶子（见第 7 节）。

**【定义 VH.2.2｜D-VH.2.2】（折扣回报的后向递推）**

**后向递推**（工程上最常用的形式）：$G_t=R_{t+1}+\gamma G_{t+1}$，从轨迹尾部往
前累加即可。对应实现 `discounted_returns`（`app/value_head.py:141`）：

**【代码 VH.2.3｜Cd-VH.2.3】（`discounted_returns`）**

```python
running = 0.0
for index in range(len(rewards) - 1, -1, -1):
    running = rewards[index] + gamma * running
    result[index] = max(-1.0, min(1.0, running))   # 截断到 [-1,1]
```

**【注 VH.2.4｜R-VH.2.4】（目标截断到 [-1,1]）**

注意实现把结果截断到 $[-1,1]$：与 Tanh 值头的输出范围一致，避免把未归一化的
大数值直接喂给 MSE（见 `clamp_target`，`app/value_head.py:135`）。

## 2. 证明搜索中的价值语义：proof-depth / remaining-steps

**【定义 VH.3.1｜D-VH.3.1】（nanoproof 的 proof-depth 价值语义）**

证明搜索的价值不是"得分越高越好"这么简单，而是一个**剩余代价**。nanoproof 的
原始定义为：

> `value` = 距离"证明完成"还需要的步数（proof depth）。**终止（证出）为 0**，
> 越大越差。

**【定义 VH.3.2｜D-VH.3.2】（REAP 标量价值头的归一化目标）**

REAP 的标量价值头把负的剩余步数归一化到 $[-1,0]$：

$$
\text{target}(d)=-\frac{\min(d,\,D_{\max})}{D_{\max}},
\qquad D_{\max}=64,
$$

即 `proof_depth_to_target(depth, max_depth=64) = -min(d,64)/64`
（`app/value_head.py:155`）。于是 $d=0 \Rightarrow 0$（最好），
$d\ge 64 \Rightarrow -1$（最差、饱和）。

**【定义 VH.3.3｜D-VH.3.3】（GPU 分类语义：distance 1–64）**

在 GPU 版的分类语义里，方向被翻正为**距离** $d\in[1,64]$，其中桶 64 饱和
（"所有 $\ge 64$ 的距离都压到 64"）：

```
VALUE_SEMANTICS = "new_value_head.distance_categorical_64_saturated.v1"
DECODE = "softmax-temperature-1-expected-distance-1-to-64-bin64-saturates"
```

（`gpu_runtime/categorical_search_backend.py:38`）。两套符号的换算关系是
$\text{value} \approx -\text{distance}/64$；collector 客户端会在 Lean 侧再取负
（见 `PORTING_REAP_VALUE_HEAD.md` 的映射表）。

**【注 VH.3.4｜R-VH.3.4】（nanoproof 的桶 token 生成）**

nanoproof 侧更直接：它让模型在 `<|value|>` 之后**生成一个桶 token**，桶固定为
64 个特殊 token：

**【代码 VH.3.5｜Cd-VH.3.5】（64 桶 token 定义）**

```python
# nanoproof/nanoproof/tokenizer.py
*[f"<|bin_{i:02d}|>" for i in range(1, GLOBAL_CONFIG.num_value_bins + 1)]
# GLOBAL_CONFIG.num_value_bins = 64  (nanoproof/nanoproof/common.py:75)
```

**【注 VH.3.6｜R-VH.3.6】（桶 logits 的期望解码）**

推理时取这些桶 token 的 logits、softmax 后求期望（`nanoproof/nanoproof/inference.py:186`）：

```python
bin_token_ids = self.tokenizer.get_value_token_ids()
bin_logits = value_logits[:, bin_token_ids].float()      # (B, 64)
bin_probs  = torch.softmax(bin_logits, dim=-1)           # (B, 64)
bin_values = torch.arange(1, 64 + 1, dtype=bin_probs.dtype, device=device)
values = (bin_probs * bin_values).sum(dim=-1)            # E[distance]
```

这就是"分类价值头"解码出**连续期望**的最小实现。

## 3. 标量 vs 64-bin 分类：为什么要两种都有

### 3.1 标量头（回归）

**【定义 VH.4.1｜D-VH.4.1】（标量价值头结构）**

结构（`app/value_head.py:35`，与 `gpu_runtime/real_backend.py:245` 一致；本地实现 `code/from_scratch/value_head.py`（`F-b04-value_head`），与第 1 章【注 1.7.3】同构）：

$$
\hat V_\phi(h)=\tanh\!\big(W_2\,\mathrm{SiLU}(W_1 h+b_1)+b_2\big),
\quad W_1\in\mathbb{R}^{256\times H},\; W_2\in\mathbb{R}^{1\times 256}.
$$

- 输出天然有界，配合"归一化到 $[-1,1]$ 的回报"使用。
- 损失用 MSE 或 Huber（`ValueHeadTrainer`，`app/value_head.py:298`；MSE 见【定义 1.2.5】，与高斯 MLE 的对应见【命题 1.2.14】）。
- 头永远跑 fp32，即使 backbone 跑 bf16：`self.mlp(hidden_states.float())`
  （`app/value_head.py:63`），避免小 MLP 在 bf16 下梯度下溢。

### 3.2 分类头（64 桶）

**【定义 VH.4.2｜D-VH.4.2】（64 桶分类价值头结构）**

结构（`gpu_runtime/verified_backend.py:83`、`categorical_search_backend.py:41`；softmax 见【定义 1.2.1】）：

$$
z_\phi(h)=W_2\,\mathrm{SiLU}(W_1 h+b_1)+b_2 \in \mathbb{R}^{64},\quad
p_k=\frac{e^{z_k}}{\sum_j e^{z_j}},\quad
\hat d=\sum_{k=1}^{64} k\,p_k.
$$

**【注 VH.4.3｜R-VH.4.3】（分类头的优势与代价）**

为什么分类头更好？

1. **有界且饱和**：目标 $d\ge 64$ 时统一进桶 64，天然处理"太远"的状态，不需要
   人为 clip 目标值（clip 会引入偏差，见第 6 节）。
2. **表达不确定性**：$p$ 是完整的分布，可以算方差、熵，供搜索做风险敏感决策。
3. **校准更可控**：交叉熵是 proper scoring rule，训练目标与"预测概率分布"直接
   对应，ECE 等校准指标有明确含义（第 5 节）。
4. **目标可插值**：树备份得到的是整数步数，但某些备份给的是小数距离，two-hot
   可以把小数距离无损投影到相邻两桶（第 4 节）。

代价：需要固定桶语义、需要把连续目标离散化；若桶太粗会引入量化偏差。

## 4. two-hot 目标：把任意距离投影到相邻桶

**【定义 VH.5.1｜D-VH.5.1】（two-hot 目标）**

给定一个（可能带小数的）距离 $d\ge 1$，**two-hot** 目标把它放到相邻两桶
$\lfloor d\rfloor,\lceil d\rceil$ 上，权重按小数部分线性分配。对
$d\ge D_{\max}$ 直接饱和到桶 $D_{\max}$（权重 1）。

$$
\hat d = \min(d,\,D_{\max}),\quad
\ell = \lfloor \hat d\rfloor,\quad u=\lceil \hat d\rceil,\quad
w_u = \hat d-\ell,\quad w_\ell = 1-w_u
$$

$$
y_k = w_\ell\,\mathbf{1}[k=\ell]+w_u\,\mathbf{1}[k=u].
$$

对应 `distance_two_hot`（`gpu_runtime/categorical_search_backend.py:96`）：

**【代码 VH.5.2｜Cd-VH.5.2】（`distance_two_hot`）**

```python
clipped = min(distance, float(support_max))
lower, upper = math.floor(clipped), math.ceil(clipped)
upper_weight = clipped - lower
lower_weight = 1.0 - upper_weight
weights = [0.0] * support_max
weights[lower - 1] += lower_weight
if upper_weight:
    weights[upper - 1] += upper_weight
```

**【定义 VH.5.3｜D-VH.5.3】（two-hot 交叉熵损失）**

损失是"目标分布 $y$ 与预测分布 $p$ 的交叉熵"（`categorical_search_backend.py:288`；交叉熵见【定义 1.2.4】）：

$$
\mathcal{L}_{\text{cat}}=-\sum_{k=1}^{64} y_k \log p_k .
$$

因为 $y$ 只在 1–2 个桶非零，它实际是在优化"把概率质量放到正确的桶附近"。
解码仍用期望 $\hat d=\sum_k k p_k$（`categorical_search_backend.py:284`），
并把结果夹到 $[1,64]$ 防浮点越界。

**【注 VH.5.4｜R-VH.5.4】（two-hot 与硬整数类变体）**

> 变体：`verified_backend.py:275` 用的是**硬整数类** `cross_entropy`（目标
> `value_class` 是整数），属于 one-hot 版分类；`categorical_search_backend.py`
> 用 two-hot 以支持小数距离。两者结构相同、只差目标构造。

## 5. 校准与 proper scoring

价值头最终被搜索用来**排序 / 备份**，所以"预测值是否可信"和"预测得准不准"同等
重要。这就是校准（calibration）问题。

**【定义 VH.6.1｜D-VH.6.1】（proper scoring rule）**

**Proper scoring rule**：一个得分函数 $S(p,y)$ 是 proper 的，当且仅当在数据真实
分布下，报告真实分布 $p^{*}$ 的期望得分最优（最小化损失）。MSE 对**均值**是
proper 的，交叉熵（log loss）对**完整分布**是 proper 的。因此：

**【注 VH.6.2｜R-VH.6.2】（MSE/CE 的 properness 推论）**

- 标量头 + MSE $\Rightarrow$ 头学到的是条件均值 $\mathbb{E}[G\mid s]$，但无法表达
  方差；若回报分布重尾，均值会被少数大值主导（高方差），应改用 Huber 抑制离群。
- 分类头 + 交叉熵 $\Rightarrow$ 头学的是完整条件分布，可进一步做风险敏感备份。

**【定义 VH.6.3｜D-VH.6.3】（可靠性图与 ECE）**

**可靠性图（reliability diagram）与 ECE**：把预测按置信度分桶，统计每桶的
平均预测与平均真实标签。期望校准误差（Expected Calibration Error）为：

$$
\mathrm{ECE}=\sum_{m=1}^{M}\frac{|B_m|}{n}\,\big|\,\mathrm{acc}(B_m)-\mathrm{conf}(B_m)\,\big| .
$$

在回归价值头上，"置信度"可换成预测分位或桶概率；对分类头可直接用
$\max_k p_k$。N11 notebook 会画出 reliability 曲线并报告 ECE。

**【注 VH.6.4｜R-VH.6.4】（温度缩放）**

**温度缩放**：若分类头过置信/欠自信，可只学一个标量 $T$ 做
$p=\mathrm{softmax}(z/T)$，不改变预测序，只改变校准。这与 RLHF 的 reward model
校准同源。

## 6. 方差与偏差：目标从哪里来

**【注 VH.7.1｜R-VH.7.1】（偏差—方差来源）**

价值头的监督信号来自搜索/回放，本身就带噪，理解偏差—方差来源很关键：

1. **蒙特卡洛回报的方差**：树越浅、采样越少，$\hat G$ 方差越大。故训练时常用
   EMA 目标、更多 backup、或直接使用树搜索备份值（REAP 的
   `value_trace.distance`，见 `search_backend.py:132`）。
2. **折扣截断偏差**：$\gamma<1$ 时 $G_t$ 忽略远期奖励，引入系统偏差；证明任务里
   常把 $\gamma$ 设得接近 1（`discounted_returns` 默认 `gamma=0.99`，
   `app/value_head.py:141`），或直接按"剩余步数"而不是折扣回报建模。
3. **目标饱和偏差**：桶 64 把 $d>64$ 全部并成一类，估计的
   $\mathbb{E}[k]$ 会**低估**真实距离。这是有意的偏差换稳定（避免无界回归）。
4. **策略漂移偏差**：$\pi$ 更新后旧回报失效，故 REAP 的 RTTT 让策略与价值头
   同步更新（`policy_server.py` 同时把 `vhead` 加入优化器参数组）。
5. **Huber vs MSE**：Huber 在 $|\hat V-y|>\delta$ 时退化为 L1，梯度有界，对
   离群回报更稳；MSE 对均值无偏但方差敏感。

重尾/不确定性强的场景应优先分类头（保留分布），或对回报做 winsorize / 归一化。

## 7. 与 MCTS 的 Q 变换关系

**【定义 VH.8.1｜D-VH.8.1】（PUCT 选择与 Q 统计量）**

MCTS（《07-MCTS+V1/01-MCTS原理与V1闭环.md》）选择阶段用树内统计量：

$$
Q(s,a)=\frac{1}{N(s,a)}\sum_{i}G_i(s,a),\qquad
\mathrm{PUCT}(s,a)=Q(s,a)+c\,P(s,a)\frac{\sqrt{\sum_b N(s,b)}}{1+N(s,a)}.
$$

**【定义 VH.8.2｜D-VH.8.2】（叶子评估与备份）**

当到达叶子时调用价值头评估 $V_\phi(s_L)$，再把备份值沿路径回传：

$$
Q(s,a) \leftarrow r + \gamma\, V_\phi(s'),\qquad
V(s) \leftarrow \frac{1}{N(s)}\sum_a N(s,a)Q(s,a).
$$

**【注 VH.8.3｜R-VH.8.3】（工程约定：符号、距离与 RTTT）**

几个关键工程约定：

- **符号 / negamax**：Reap 的 `Generator.lean` 把 value 的 `score` 取负使用
  （`PORTING_REAP_VALUE_HEAD.md`），即 score $=-V$。所以同一套网络在不同模块里
  可能看到符号相反的"价值"。
- **距离 vs 回报**：搜索备份预测的是**距离** $d$（越小越好），价值头预测的是
  回报（越大越好），二者通过 $V \approx -d/64$ 或 `value_to_distance`
  （`search_backend.py:103`，含 `value_floor` 与 `gamma`）互换。
- **未访问惩罚**：`unvisited_value_penalty`（`nanoproof/search.py:74`）给未展开
  子节点一个悲观初值，防止搜索被价值头的乐观误差带偏——用先验对抗价值误差。
- **RTTT 中的价值损失**：在线更新时，value loss 与 policy loss、KL 一起加权
  （`real_backend.py:621` 的 `mse_loss(value_prediction, value_target)`；
  `verified_backend.py:275` 的 `cross_entropy(logits, value_class)`），
  权重为 `--value-coefficient` / `value_coefficient`。
- **搜索价值损失**：分类搜索里，目标来自 `value_trace.distance`，经 two-hot 后
  用交叉熵（`categorical_search_backend.py:307`）。

一句话：价值头是 MCTS 的**叶子评估器（leaf evaluator）**，Q 是搜索树对价值的
**自举（bootstrap）**；分类头让这个自举发生在分布空间而非均值空间。

## 9. 小结与延伸

**【注 VH.10.1｜R-VH.10.1】（小结与延伸）**

- 价值 = "从当前证明状态到证出还需多少代价"的期望；标量头学条件均值，分类头学
  条件分布。
- 标量头：Tanh 有界 + MSE/Huber，简单但无分布、对离群敏感。
- 分类头：64 桶 + two-hot + 交叉熵，有界、饱和、可校准、可算不确定性。
- 校准（ECE / reliability / temperature scaling）不是可选项——搜索直接用价值
  排序，系统性过/欠自信会直接损害搜索质量。
- 与 MCTS 的关系是"叶子评估 + 自举备份"，注意符号（negamax）与"价值/距离"两套
  语义的换算。
