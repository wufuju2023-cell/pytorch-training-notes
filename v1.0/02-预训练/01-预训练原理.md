# 01 · 预训练原理

本章讲清"为什么要预训练、预训练在优化什么、怎么在工程上跑起来"，并逐条对照
AlphaProof 的 nanoproof 预训练实现（`nanoproof/pretrain.py` 在 Nemotron-CC-Math，
`nanoproof/midtrain.py` 在 Lean-GitHub）。配套代码见
[`code/from_scratch/pretrain.py`](code/from_scratch/pretrain.py) 与
[`code/with_api/pretrain_hf.py`](code/with_api/pretrain_hf.py)。

## 1. 预训练在流水线中的位置

```
pretrain (通用数学+代码) -> midtrain (Lean 代码) -> SFT (state->tactic) -> RL (搜索+验证)
```

预训练提供"语言与数学的分布"；midtrain 把分布收缩到 Lean；SFT 教会"给定状态输出下一步
tactic"；RL 用 MCTS + 验证器把策略推向"真的能证出定理"。本篇只讲前两步。

| 阶段 | 数据 | 学到什么 |
|---|---|---|
| 预训练 | 网页数学 + Lean 源码（海量、无标注） | 词法、语法、常见推理套路 |
| SFT | (state, tactic) 对 | 对齐到"下一步 tactic" |
| RL | 与环境交互的成功/失败 | 提升可证明率 |

## 2. 语言建模目标

给定 token 序列 $x=(x_1,\dots,x_T)$，自回归模型用链式法则分解联合分布：

$$
p_\theta(x)=\prod_{t=1}^{T} p_\theta(x_t\mid x_{<t})
$$

每个因子由 softmax 给出：设 $z_t=\mathrm{GPT}_\theta(x_{<t})\in\mathbb{R}^{V}$ 是第 $t$
步的 logits，则

$$
p_\theta(x_t\mid x_{<t})=\mathrm{softmax}(z_t)_{x_t}
=\frac{\exp(z_{t,x_t})}{\sum_{v=1}^{V}\exp(z_{t,v})}
$$

**Teacher forcing（教师强制）**：训练时第 $t$ 步的条件是**真实**前缀 $x_{<t}$，而不是
模型上一刻自己生成的 token。因此所有位置的预测可以一次前向并行计算（标签就是输入右移
一位），这正是 Transformer 训练高效的原因。推理时没有真值，只能自回归逐 token 生成。

## 3. 从最大似然到交叉熵

$$
\mathcal{L}(\theta)=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t})
$$

最小化它就是最大似然估计（MLE）。它等于真实分布 $p_{\text{data}}$ 与模型分布
$p_\theta$ 的交叉熵：

$$
H(p_{\text{data}},p_\theta)=-\mathbb{E}_{x\sim p_{\text{data}}}\log p_\theta(x)
=H(p_{\text{data}})+\mathrm{KL}\!\left(p_{\text{data}}\,\Vert\,p_\theta\right)
$$

由于 $H(p_{\text{data}})$ 与 $\theta$ 无关，最小化交叉熵等价于最小化
$\mathrm{KL}(p_{\text{data}}\Vert p_\theta)$，即让模型分布逼近数据分布。

**逐位置形式。** 实际代码对 $T$ 个位置取平均（`F.cross_entropy(..., ignore_index=-100)`）：

$$
\mathcal{L}(\theta)=-\frac{1}{\sum_t m_t}\sum_{t=1}^{T} m_t \log p_\theta(x_t\mid x_{<t})
$$

其中 $m_t\in\{0,1\}$ 是**标签掩码**。预训练里所有位置都算（$m_t\equiv 1$）；SFT 里
prompt 位置 $m_t=0$（用标签 `-100` 表示），只在答案 token 上算损失——详见 03-SFT。

## 4. 梯度推导要点

令第 $t$ 步 softmax 前的 logits 为 $z\in\mathbb{R}^V$，真实类别为 $c$。单点损失
$\ell=-\log \mathrm{softmax}(z)_c$ 对 logits 的梯度是经典结论：

$$
\frac{\partial \ell}{\partial z_v}=\mathrm{softmax}(z)_v-\mathbb{1}[v=c]
$$

推导：$\log\mathrm{softmax}(z)_c=z_c-\log\sum_v e^{z_v}$，对 $z_v$ 求导得
$\mathbb{1}[v=c]-\mathrm{softmax}(z)_v$，取负即上式。

于是**梯度 = 预测概率减去 one-hot 真值**：预测越准，梯度越小；初始 loss 约为 $\ln V$
（均匀分布），训练就是不断把 $p_\theta(x_t)$ 往真值推。

## 5. 困惑度

$$
\mathrm{PPL}=\exp\!\left(\mathcal{L}\right)
=\exp\!\left(-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t})\right)
$$

均匀分布时 $p=1/V$，$\mathrm{PPL}=V$；完美预测时 $\mathrm{PPL}=1$。故**初始困惑度约等于
词表大小**：字符级 $V\approx 70$ 起步约 70；GPT-2 BPE $V\approx 50257$ 起步约 5 万。
不同 tokenizer 的 PPL 不可直接比较。

## 6. 数据配比与课程学习

nanoproof 是两段式：先 Nemotron-CC-Math（约 20B token 网页数学）做 `pretrain`，再
Lean-GitHub（约 65M token Lean 源码）做 `midtrain`，把分布推向代码/证明。设域 $d$ 的权重
为 $w_d$，batch 中来自域 $d$ 的 token 占比为

$$
\pi_d=\frac{w_d}{\sum_{d'}w_{d'}}
$$

课程学习让权重随进度 $\tau=t/T$ 从起点线性过渡到终点：

$$
\pi_d(t)=(1-\tau)\,\pi_d^{(0)}+\tau\,\pi_d^{(1)},\qquad \tau=\frac{t}{T}
$$

直觉：前期用广域网页/代码建立通用表示，后期退火到数学/Lean，避免前期在窄分布上过拟合。
`code/from_scratch/pretrain.py` 的 `domain_schedule` 即此插值。配比还兼有"防遗忘"作用：
只喂 Lean 代码会让模型丢掉自然语言推理能力（SFT 篇会再谈灾难性遗忘）。

## 7. 算力预算：target-flops 与参数-数据比

对 decoder-only Transformer，前向约 $2N$ FLOPs/token，反向约 $4N$，故

$$
C\approx 6\,N\,D
$$

$N$ 为非 embedding 参数量，$D$ 为训练 token 数。给定预算反解 token 数与迭代步数：

$$
D=\frac{C}{6N},\qquad \text{steps}=\frac{D}{B\cdot T\cdot A\cdot W}
$$

其中 $B$ 为 batch、$T$ 为序列长、$A$ 为梯度累积、$W$ 为数据并行度。Chinchilla 结论：
最优数据-参数比约 $D/N\approx 20$。本目录提供 `--target-flops` 与 `--param-data-ratio` 开关。

## 8. 并行与数值精度

**数据并行（DDP）**：同一模型复制到 $W$ 张卡，各吃不同 batch，反向时对梯度 all-reduce 求平均：

$$
g=\frac{1}{W}\sum_{w=1}^{W} g^{(w)}
$$

等价于把 batch 放大 $W$ 倍。`code/from_scratch/pretrain.py` 用
`torchrun --nproc_per_node=W` 启动，检测 `WORLD_SIZE` 后套 `DistributedDataParallel`；
`with_api` 版由 `Trainer` + accelerate 托管。

**混合精度**：fp16 需 `GradScaler` 防止小梯度下溢；bf16 指数范围同 fp32，通常免缩放，是现代
首选。softmax / 归一化应保持 fp32，`torch.autocast` 会自动处理。

**梯度累积**：小 batch 累计 $A$ 步再 step，损失除以 $A$ 保证量级不变：

$$
g=\nabla_\theta\frac{1}{A}\sum_{a=1}^{A}\mathcal{L}_a
$$

**梯度检查点**：以计算换显存，反向时重算激活；nanoproof 与容器 SFT 默认开启。

## 10. 常见坑

1. **shift 方向写反**：标签必须右移一位（$y_t=x_{t+1}$）。写错时 loss 仍会降，但模型
   学的是"复制输入"，生成时立刻露馅。
2. **掩码误用**：预训练阶段**不要**用 `-100` 屏蔽；那是 SFT 才需要的。预训练一旦把大量
   token 置 -100，等效数据量骤降。
3. **loss 不降**：先查学习率（1e-3 到 3e-4 之间试）、再看语料是否过短、最后查是否忘了
   `optimizer.zero_grad()`。
4. **PPL 比大小**：不同 tokenizer 不可比；跨实验务必用同一分词器。
5. **过拟合**：小语料上验证 loss 很快抬头，属正常；真实预训练靠海量数据避坑。

## 11. 小结与练习

- 预训练 = 最小化 next-token 交叉熵 = 最大化似然 = 最小化与数据分布的 KL（差一个常数）。
- 梯度就是 `softmax(z) - onehot(y)`，干净且有界。
- 困惑度是交叉熵的指数，起步约等于词表大小。
- 算力预算 $C\approx 6ND$，由此反解数据量与步数；Chinchilla 比例约 20。
- 与 nanoproof 的对应：`pretrain.py`（网页数学）+ `midtrain.py`（Lean 代码）。

练习：跑 `code/from_scratch/pretrain.py --config micro`，把 `--domains` 在 `"math:1"`
与 `"math:1,code:1,web:1"` 之间切换，比较验证 loss 曲线；再用 `--target-flops 1e13`
感受预算如何决定步数；最后把 `--resume` 指向刚存出的 checkpoint 并换 `--domains code:1`，
体会 nanoproof 的 midtrain。
