## 4.1 为什么需要子词分词

**【注 4.1.1｜R-4.1.1】（子词分词的动机）**

语言模型的输入是整数 token 序列，但文本是 Unicode 字符串。字符级序列过长，词级会遇到未登录词（OOV）与词表爆炸。**子词（subword）** 分词在两者之间折中：

- 高频词保持为单个 token（`the`、`Lemma`）；
- 低频词拆成子词（`tokenization` -> `token` + `ization`）；
- 任意字符串都能被拆解，永不 OOV。

**【定义 4.1.2｜D-4.1.2】（分词映射）**

形式上，分词器定义映射

$$
\mathrm{tok}: \Sigma^{*} \to \mathbb{N}^{L},
$$

语言模型真正建模的是 token 序列上的分布 $p(x_1, \ldots, x_L)$。

## 4.2 字符级、BPE 与 WordPiece

**【注 4.2.1｜R-4.2.1】（字符级、BPE、WordPiece、Unigram 对比）**

- **字符级**：词表 = 字符集。无 OOV、词表小，但序列极长、单 token 语义稀薄。
- **BPE（Byte-Pair Encoding）**：从字符出发，反复合并语料中最高频的相邻 token 对，直到达到目标词表大小。GPT 系列采用。
- **WordPiece**：合并准则为**似然增益**而非频数；用 `##` 标记词内续接（`token` -> `tok` + `##en`）。BERT 采用。
- **Unigram / SentencePiece**：从大词表出发按概率删减，用 EM 训练；把空格也当作符号（`_`），对中文/Lean 更友好。

## 4.3 训练一个 BPE 的算法

**【算法 4.3.1｜A-4.3.1】（BPE 训练算法）**

BPE 训练是贪婪的最大频率合并：

```text
输入：语料 C，目标词表大小 V
1. 每个词的字符间加结束符，初始词表 = 所有字符 + 结束符
2. while 词表大小 < V:
3.     统计所有相邻 token 对的频数
4.     合并频数最大的对 (a, b) 为新 token a+b
5.     替换语料中的 (a, b) 并记录合并规则
6. 输出：词表 + 有序合并规则
```

**【注 4.3.2｜R-4.3.2】（BPE 编码）**

编码时按记录顺序依次应用合并规则。

```python
from collections import Counter

def train_bpe(corpus, vocab_size):
    words = [list(w) + ["</w>"] for w in corpus.split()]
    vocab = Counter(t for w in words for t in w)
    merges = []
    while len(vocab) < vocab_size:
        pairs = Counter()
        for w in words:
            for a, b in zip(w, w[1:]):
                pairs[(a, b)] += 1
        if not pairs:
            break
        (a, b), _ = pairs.most_common(1)[0]
        merges.append((a, b))
        vocab[a + b] += 1
        new_words = []
        for w in words:
            out, i = [], 0
            while i < len(w):
                if i + 1 < len(w) and w[i] == a and w[i + 1] == b:
                    out.append(a + b); i += 2
                else:
                    out.append(w[i]); i += 1
            new_words.append(out)
        words = new_words
    return vocab, merges

vocab, merges = train_bpe("low lower lowest new newer newest", 50)
print(len(vocab), merges[:5])
```

**【注 4.3.3｜R-4.3.3】（BPE 复杂度）**

朴素实现复杂度 $O(V \cdot \text{len})$；工业实现（HuggingFace `tokenizers`）用优先队列把每轮降到近似对数级。

## 4.4 特殊 token

**【注 4.4.1｜R-4.4.1】（nanoproof 追加的特殊 token）**

`nanoproof/tokenizer.py` 的 `SPECIAL_TOKENS` 在 GPT-2 BPE 之上追加三类 token：

```python
SPECIAL_TOKENS = [
    "<|pad|>",
    "<|tactic|>",
    "<|value|>",
    *[f"<|bin_{i:02d}|>" for i in range(1, GLOBAL_CONFIG.num_value_bins + 1)],
    # Mathlib 中出现 >= 1000 次、但 GPT-2 无专属 token 的 Unicode 符号
    "ˢ", "ˣ", "Γ", "Δ", "Λ", "Σ", "Ω", "θ", "φ", "ψ",
    "ℂ", "ℕ", "ℚ", "ℝ", "ℤ", "∀", "∃", "∈", "∉", "∑", "∏", "≤", "≥", "⊆", "⟨", "⟩", ...
]
```

| token | 用途 |
| --- | --- |
| `<|pad|>` | padding，配合 attention mask / loss mask |
| `<|tactic|>` | 标记一段 tactic 的开始，用于 SFT/RL 数据切分 |
| `<|value|>` | 标记价值输出位置，供 value head 读取 |
| `<|bin_XX|>` | **价值桶** token，$XX = 01, \ldots, 64$，把连续价值离散成 64 桶 |
| Unicode 数学符号 | 让 Mathlib 高频符号成为单 token，缩短 Lean 证明序列 |

**【注 4.4.2｜R-4.4.2】（特殊 token 的注册机制）**

底层 tokenizer 是 GPT-2 BPE，特殊 token 通过 `get_added_tokens_decoder` 注册；`get_special_tokens()` 就是读取它们。

**【注 4.4.3｜R-4.4.3】（为什么补数学符号）**

> **为什么补数学符号**：GPT-2 没见过 `ℝ`、`≤`、`∀`，会把它们拆成多个字节级 token，导致 Lean 状态序列过长、语义碎片化。提为单 token 既缩短序列又保留数学语义。

## 4.5 Lean 代码分词的特殊注意点

**【注 4.5.1｜R-4.5.1】（Lean 代码分词注意点）**

1. **Unicode 与多字节字符**：Lean 大量使用 `∀ ∃ ∈ ≤ ⟶ ⟨ ⟩`。字节级 BPE 能覆盖一切字符但会拆碎，因此专门收录高频符号为特殊 token。
2. **`<|bin_XX|>` 价值桶**：连续价值离散化：

```python
def value_to_token_ids(tokenizer, value: int) -> list[int]:
    assert 1 <= value <= GLOBAL_CONFIG.num_value_bins
    bin_token = f"<|bin_{value:02d}|>"
    return [tokenizer.encode_special(bin_token)]
```

   `token_ids_to_value` 反向还原为 $1..64$。`num_value_bins` 必须与 tokenizer 中 `<|bin_XX|>` 个数严格一致（`common.py` 注释明确要求）。
3. **`<proof_gap>` 等语义标记**：容器内 Qwen / REAL-Prover 数据格式用 `<proof_gap>` 等占位符标记证明中省略/待补的步骤，让模型学习"跳过已知展开、聚焦待补位置"。这类领域标记必须以精确匹配编码（`encode_special`），否则会被 BPE 拆碎。
4. **空白与换行敏感**：Lean 对缩进/换行敏感，`add_prefix_space`、`padding_side` 会影响状态重建。`train_value_head.py` 显式设置 `tokenizer.padding_side = "right"`。
5. **BOS/EOS**：`get_bos_token_id` / `get_eos_token_id` 都映射到 `<|endoftext|>`，文档拼接依赖它切分样本。

## 4.6 与数据管线、训练的衔接

**【注 4.6.1｜R-4.6.1】（与数据管线、训练的衔接）**

- **序列长度**：`state_max_len=640` + `tactic_max_len=128` = `max_seq_len=768`，dataloader 据此硬截断。
- **token_bytes**：`get_token_bytes` 读取 `token_bytes.pt`，把 token 映射到 UTF-8 字节数，用于 bits-per-byte（bpb）指标——比 per-token loss 更能公平比较不同分词器。
- **padding 与 mask**：`<|pad|>` 配合 `padding_side`，在 `F.cross_entropy(..., ignore_index=-1)` 处排除 padding（交叉熵见【定义 1.2.4】，掩码见【注 1.7.2】）。
- **词表大小**：`NetworkConfig.vocab_size` 决定 embedding 与 `lm_head` 规模；`Transformer` 把词表 padding 到 64 的倍数以提升矩阵乘效率。

## 4.7 一段可运行的 tokenizer 实验

**【例 4.7.1｜E-4.7.1】（GPT-2 分词实验）**

```python
from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("gpt2")
text = "theorem foo (x : R) : x <= x := le_refl x"
ids = tok(text, add_special_tokens=False)["input_ids"]
print(len(ids), [tok.decode([i]) for i in ids])
```

要加入自定义特殊 token，先 `tok.add_special_tokens({"additional_special_tokens": SPECIAL_TOKENS})` 再 `tok.save_pretrained(...)`——这正是 `nanoproof` 的 `tok_build.py` 所做的事（见 `tokenizer.py` 顶部注释）。

## 4.8 小结

**【注 4.8.1｜R-4.8.1】（小结）**

1. 子词分词在字符级与词级之间折中；BPE 用频率合并、WordPiece 用似然增益。
2. BPE 训练 = 迭代合并最高频相邻对；编码 = 按序应用合并规则。
3. `nanoproof` 在 GPT-2 BPE 上追加 `<|pad|>`、`<|tactic|>`、`<|value|>`、`<|bin_XX|>` 与 Lean 高频 Unicode 符号。
4. 价值桶 token 离散化连续价值，`num_value_bins` 必须与词表一致。
5. Lean/数学文本要特别关注 Unicode 覆盖、语义标记精确匹配与序列长度。
