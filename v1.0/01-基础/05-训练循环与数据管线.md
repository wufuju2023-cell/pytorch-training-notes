## 5.1 Dataset 与 DataLoader

### 5.1.1 抽象

**【定义 5.1.1｜D-5.1.1】（Dataset 与 DataLoader）**

PyTorch 的数据管线由两部分组成：

- `Dataset`：定义"第 $i$ 个样本"以及样本总数 `__len__`；
- `DataLoader`：负责批组合（collate）、打乱、并行加载、预取。

对于语言模型，样本通常是定长 token 序列 $(x, y)$，其中 $y$ 相对 $x$ 右移一位：$y_t = x_{t+1}$。训练目标是最小化逐位置交叉熵（【定义 1.2.4】）逐位置交叉熵（【定义 1.2.4】）

$$
L(\theta) = -\frac{1}{B T} \sum_{b=1}^{B} \sum_{t=1}^{T} \log p_\theta\!\left( y_{b,t} \mid x_{b, \le t} \right) .
$$

### 5.1.2 流式数据与断点状态

**【注 5.1.2｜R-5.1.2】（流式数据与数据游标）**

`nanoproof` 的数据是**流式**的（`nemotron_batches_with_state` 每次 `next` 返回 `(x, y, dataloader_state_dict)`），便于在任意步保存/恢复数据游标。`pretrain.py` 把 `dataloader_state_dict` 一并写入 checkpoint：

```python
x, y, dataloader_state_dict = next(train_loader)
...
train_loader = nemotron_batches_with_state(
    ..., resume_state_dict=dataloader_resume_state_dict)
```

这样续训不会重复或跳过数据。

## 5.2 Padding、Attention Mask 与 Loss Mask

### 5.2.1 Padding

**【定义 5.2.1｜D-5.2.1】（Padding）**

变长样本组成 batch 时必须补齐到同一长度。`train_value_head.py` 用右 padding：

```python
tokenizer.padding_side = "right"
encoded = tokenizer(prompts, return_tensors="pt", padding=True, truncation=False)
```

padding 位用 `<|pad|>` 填充，其 token id 与模型词表一致。

### 5.2.2 Attention mask

**【定义 5.2.2｜D-5.2.2】（Attention mask）**

padding 位不应被注意力读到，否则会污染表示。attention mask 把 padding 位置的注意力权重置 0（等价于在 softmax 前加 $-\infty$）。它由 `tokenizer` 自动产生并随 batch 传入模型。

### 5.2.3 Loss mask

**【定义 5.2.3｜D-5.2.3】（Loss mask）**

即使 attention 已屏蔽 padding，损失函数仍需屏蔽 padding 位置的预测，否则模型会学着去预测 padding。`nanoproof` 把不该计入损失的标签设为 `-1`，并在交叉熵里用 `ignore_index=-1`（交叉熵见【定义 1.2.4】，掩码见【注 1.7.2】）：

```python
loss = F.cross_entropy(
    logits.view(-1, logits.size(-1)),
    targets.view(-1),
    ignore_index=-1,
    reduction=loss_reduction,
)
```

`sft.py` / `rl.py` 也用 per-token 掩码把某些 token 排除：

```python
token_mask = train_targets >= 0          # (B, T)
weighted_token_loss = per_token_loss * sample_weights.unsqueeze(1)
loss = (weighted_token_loss * token_mask).sum() / token_mask.sum()
```

- `per_token_loss = model(..., loss_reduction="none")` 得到每个位置的损失；
- `token_mask` 排除 padding 或不应监督的 token；
- `sample_weights` 给不同样本（例如价值样本 vs 策略样本）不同权重。

**【注 5.2.4｜R-5.2.4】（价值头与策略头的多任务损失）**

> **价值头与策略头共享损失**：`sft.py` 报告 `Critic argmax MSE`、`Critic soft MSE`，说明价值预测的损失与策略 token 损失在同一个 batch 里加权求和。这是"多任务损失"的典型实现。

## 5.3 梯度累积

**【定义 5.3.1｜D-5.3.1】（梯度累积）**

显存限制了单次前向的 batch 大小。**梯度累积**用多次 micro-batch 的前向/反向累积梯度，再统一更新，从而模拟大 batch：

$$
g_{\text{accum}} = \frac{1}{K} \sum_{k=1}^{K} \nabla_\theta L_k, \qquad
\theta \leftarrow \theta - \eta \, g_{\text{accum}} .
$$

由于 PyTorch 的 `.grad` 是累加语义（见【注 2.1.2】），实现只需在每次 micro-batch 把 loss 除以 $K$：

```python
grad_accum_steps = total_batch_size // world_tokens_per_fwdbwd
...
for micro_step in range(grad_accum_steps):
    loss = model(x, y)
    loss = loss / grad_accum_steps       # 关键：归一化
    if scaler is not None:
        scaler.scale(loss).backward()
    else:
        loss.backward()
    x, y, dataloader_state_dict = next(train_loader)
# 累积 K 次后统一 optimizer.step()
```

**【注 5.3.2｜R-5.3.2】（reduction 与等效学习率）**

注意如果前面用的是 `reduction="sum"`，就要按累积步数正确处理分母，否则等效学习率会随 $K$ 漂移。

## 5.4 混合精度：fp16 / bf16 / GradScaler

### 5.4.1 两种低精度格式

**【注 5.4.1｜R-5.4.1】（fp16 与 bf16 对比）**

| 格式 | 总位数 | 指数位 | 尾数位 | 特点 |
| --- | --- | --- | --- | --- |
| fp16 | 16 | 5 | 10 | 动态范围窄（约 $6 \times 10^{4}$），需 GradScaler |
| bf16 | 16 | 8 | 7 | 范围同 fp32，精度略低，通常无需缩放 |

### 5.4.2 GradScaler 原理

**【定义 5.4.2｜D-5.4.2】（GradScaler 原理）**

fp16 下小梯度会下溢为 0。GradScaler 先把损失乘以 $S$：

$$
L' = S \cdot L \;\Rightarrow\; \nabla_\theta L' = S \cdot \nabla_\theta L,
$$

反向后梯度被放大，避免了小值下溢；`step` 之前再除以 $S$ 还原。若某步出现 inf/NaN，则跳过该步并减小 $S$；若连续多步无溢出，则增大 $S$。

```python
scaler = torch.amp.GradScaler() if COMPUTE_DTYPE == torch.float16 else None
...
if scaler is not None:
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)
    scaler.step(optimizer)
    scaler.update()
else:
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), grad_clip)
    optimizer.step()
```

注意 `unscale_` 必须在裁剪之前，否则裁剪的是被放大过的梯度，阈值失去意义。bf16 训练（`COMPUTE_DTYPE` 为该类型时）直接把 `scaler` 设为 `None`，走 else 分支。

### 5.4.3 显式 dtype 管理

**【注 5.4.3｜R-5.4.3】（显式 dtype 管理）**

`nanoproof` 不使用 autocast，而是自定义 `Linear` 在 forward 里把权重转成激活 dtype：

```python
class Linear(nn.Linear):
    def forward(self, x):
        return F.linear(x, self.weight.to(dtype=x.dtype))
```

主权重保持 fp32 以维持优化器精度，matmul 用 bf16 以提速。注释明确写道："master weights stay fp32 for optimizer precision, but matmuls run in the activation dtype"。

## 5.5 梯度检查点（activation checkpointing）

**【定义 5.5.1｜D-5.5.1】（梯度检查点）**

反向传播需要前向的中间激活，显存随深度线性增长。**梯度检查点**只保存少量"检查点"，反向时重算中间激活（显存账见【注 1.3.8】）：

- 显存：从 $O(L)$ 降到 $O(\sqrt{L})$（按段划分）；
- 代价：多一次前向，约 30% 额外计算。

PyTorch 接口：`torch.utils.checkpoint.checkpoint(fn, x)`。`nanoproof` 未在主路径使用，但 `checkpoints.py` 承担模型/优化器状态的保存加载。当显存紧张时，检查点换显存是最直接的手段。

## 5.6 Checkpoint 与断点续训

### 5.6.1 保存内容

**【定义 5.6.1｜D-5.6.1】（checkpoint 的内容）**

一次完整的 checkpoint 应包含：

- 模型权重（`model.state_dict()`）；
- 优化器状态（`optimizer.state_dict()`，含动量与自适应矩）；
- 训练进度（`step`、`epoch`）；
- 数据游标（`dataloader_state_dict`）；
- 监控状态（`min_val_bpb`、`smooth_train_loss`、`total_training_time`）；
- 随机数状态；
- 元信息（`model_config`、`user_config`）。

`pretrain.py` 的 `save_checkpoint` 传入：

```python
save_checkpoint(
    model_dir, step, orig_model.state_dict(), optimizer.state_dict(),
    {"step": step, "val_bpb": val_bpb, "model_config": model_config_kwargs,
     "user_config": user_config, "dataloader_state_dict": dataloader_state_dict,
     "loop_state": {...}},
    rank=ddp_rank,
)
```

恢复时 `optimizer.load_state_dict(optimizer_data)` 并读回 `step`、`loop_state`、数据游标。

### 5.6.2 原子写入

**【定义 5.6.2｜D-5.6.2】（原子写入）**

`value_head.py::save_value_head` 演示了**原子写**：先写临时文件再用 `os.replace` 原子替换，避免中断留下半截 checkpoint：

```python
fd, temporary = tempfile.mkstemp(prefix=..., dir=str(destination.parent))
torch.save(payload, temporary)
os.replace(temporary, destination)
```

这是长训练任务的基本工程纪律（与"断点续传"原则一致）。

## 5.7 日志与指标

### 5.7.1 语言模型指标：per-token loss 与 bpb

**【定义 5.7.1｜D-5.7.1】（per-token loss 与 bpb）**

训练损失是平均交叉熵（nats/token）。跨分词器比较时更公平的指标是 **bits-per-byte**：

$$
\text{bpb} = \frac{L_{\text{nats/token}}}{\log 2 \cdot \text{tok\_per\_byte}} .
$$

`get_token_bytes` 加载 `token_bytes.pt`（每个 token 的 UTF-8 字节数），`evaluate_bpb` 据此计算验证集 bpb。`pretrain.py` 记录 `smooth_train_loss`、`min_val_bpb`、`total_training_time`。

### 5.7.2 任务指标

**【注 5.7.2｜R-5.7.2】（任务指标）**

`sft.py` 报告：

- `Tactic full accuracy`：整段 tactic 完全匹配的比例；
- `Tactic first token accuracy`：首个 tactic token 命中率；
- `Critic argmax MSE` / `Critic soft MSE`：价值预测误差。

`train_value_head.py` 每 epoch 打印 `loss`、`hidden_size`、`steps`，并在结束时输出 checkpoint receipt。

### 5.7.3 记录系统

**【注 5.7.3｜R-5.7.3】（记录系统）**

`nanoproof` 用 `create_metrics_logger` 把指标写入 JSONL，并把 stdout/stderr 落盘到 `log_dir`；分布式下按 rank 记录 `errors.jsonl`。这些日志是排查发散、过拟合、数据问题的第一手证据。

## 5.8 一段可运行的训练管线

**【例 5.8.1｜E-5.8.1】（最小可运行训练管线）**

```python
import torch
from torch.utils.data import Dataset, DataLoader

class ToyLMData(Dataset):
    def __init__(self, n=256, seq=32, vocab=64):
        self.x = torch.randint(0, vocab, (n, seq))
    def __len__(self):
        return len(self.x)
    def __getitem__(self, i):
        x = self.x[i]
        return x[:-1], x[1:]          # 输入 / 右移目标

def collate(batch):
    xs, ys = zip(*batch)
    return torch.stack(xs), torch.stack(ys)

loader = DataLoader(ToyLMData(), batch_size=8, shuffle=True, collate_fn=collate)
model = torch.nn.Embedding(64, 32)     # 占位模型
head = torch.nn.Linear(32, 64)
opt = torch.optim.AdamW(list(model.parameters()) + list(head.parameters()), lr=3e-4)
scaler = torch.amp.GradScaler()
accum = 4

step = 0
for epoch in range(2):
    opt.zero_grad()
    for i, (x, y) in enumerate(loader):
        with torch.amp.autocast("cpu", dtype=torch.bfloat16):
            logits = head(model(x))
            loss = torch.nn.functional.cross_entropy(
                logits.reshape(-1, 64), y.reshape(-1), ignore_index=-1)
        scaler.scale(loss / accum).backward()
        if (i + 1) % accum == 0:
            scaler.unscale_(opt)
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            scaler.step(opt); scaler.update(); opt.zero_grad()
            step += 1
    print("epoch", epoch, "step", step)
```

## 5.9 小结

**【注 5.9.1｜R-5.9.1】（小结）**

1. 数据管线 = `Dataset`（定长样本）+ `DataLoader`（批组合、乱序、预取、流式游标）。
2. padding 必须配 attention mask；标签必须配 loss mask（`ignore_index=-1` 或 per-token mask）。
3. 梯度累积模拟大 batch，关键是每次 micro-step 把 loss 归一化。
4. fp16 用 GradScaler 防下溢；bf16 与 fp32 不用；务必 `unscale_` 后再裁剪。
5. checkpoint 要保存权重、优化器状态、进度、数据游标并原子写入。
6. 指标要区分 per-token loss（训练用）与 bpb / 任务准确率（评估用）。
