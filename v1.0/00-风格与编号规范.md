# 00 · 风格与编号规范（v1.0）

> **【文档｜DOC-STYLE】**（doccode = `STYLE`）｜全库编号与 Tag 的唯一规范与登记表；所有 md、代码、notebook 必须按此执行。

本项目采用 Stacks Project 风格的「条目 + 编号 + Tag」体系：每个可引用对象都有全局唯一的 Tag，便于交叉引用、避免重复书写同一内容。通用教程见 opencode skill `stacks-project-style-tags`；**执行时以本文件为准，且本文件只读**（如需改动登记表，报告 lead）。

## 1. 文档条目格式

`**【<环境名> <编号>｜<Tag>】（短标题）**`

- 编号 = `<doccode>.<sec>.<item>`：`doccode` 见 §3 登记表；`sec` 为文件内小节序号（按出现顺序 1,2,3…）；`item` 为该节内**跨类型连续编号**（从 1 起）。
- Tag = `<TYPE>-<doccode>.<sec>.<item>`；证明写作 `**【证明｜Pf-<doccode>.<sec>.<item>】**`（编号与被证条目相同，不占 item 序号）。
- 类型前缀：D 定义、T 定理、P 命题、L 引理、C 推论、E 例、R 注、A 算法、Cd 代码、Ex 练习、Pf 证明。

**【注 STYLE.1.1｜R-STYLE.1.1】（示例条目）**

上面这一行就是条目的标准写法（本文件 doccode = STYLE）。

## 2. 引用与去重

- 同文件引用：`见【命题 1.2.9】`；跨文件引用：`见《05-LoRA原理》【命题 LORA.3.1】`；
- 精确检索时附 Tag：`[P-1.2.9]`；
- **示例编号必须放进反引号**（或代码块），否则会被校验脚本判为悬空引用；
- **不重复原则**：同一内容的完整陈述与证明只写一次（归宿条目），其他位置只引用编号，最多复述一句结论；
- 引用第 1 章已有结论时，用 §7 的索引查编号。
