# 00 · 09-源码精读 · 导读（全部 GPU/CPU 版本总览）

本目录逐文件精读 AlphaProof / Reap V1 家族的**所有 Python 训练与模型源码**。目标：照着读就能彻底读懂对应版本的每个文件、每个关键函数、数据流与张量形状、训练/损失/优化器、版本差异，以及“想改造应先动哪里”。

精读顺序建议**以 nanoproof 为主线**（它是唯一“从零 → 预训练 → SFT → RL → MCTS”的完整栈，其余版本都是它的局部或工程化衍生），再按“V1 app → CPU driver → gpu_runtime → value-head → 容器 QLoRA → V2 → 评测”展开。

## B. 推荐阅读顺序（nanoproof 为主线）

1. **D nanoproof 全流程**（本篇 04）：先 `model.py`/`optim.py`/`common.py`/`tokenizer.py`，再 `pretrain.py → midtrain.py → sft.py → rl.py → search.py → experience_collection.py → prover.py → engine.py → inference.py`。这是理解“一个自研训练栈长什么样”的基准。
2. **A GPU-V1 app**（本篇 01）：把 nanoproof 的 RL 思想落到“HF 模型 + LoRA + 在线 RTTT”的工程极简版。
3. **F CPU-V1 driver/runtime**（本篇 06）：闭环的 CPU 编排、观察者、传输层（`reapMCTS` 的实际驱动）。
4. **C gpu_runtime 后端**（本篇 03）：生产化 backend 家族与 64-bin 分类头，理解 V1→V1-1 的工程演进。
5. **E value-head/nanoproof 移植**（本篇 05）：价值头数据管线与 `3584→256→64` 迁移。
6. **B 容器 Qwen QLoRA SFT**（本篇 02）：Qwen3-1.7B 4bit QLoRA 监督微调 + autotune。
7. **G V2 MCTS 元动作**（本篇 07）：V2 的元动作/塔/Eff 通道，与 V1 差异。
8. **H 评测与数据集**（本篇 08）：pass@k/solve@B/校准的定义与实现。

## C. 版本之间的继承关系

```
nanoproof (D, 自研栈)
   ├─→ value-head/nanoproof 移植 (E)：把价值头思想移植到 REAL-Prover + 64-bin
   ├─→ GPU-V1 app (A)：把 RL 落成 HF+LoRA 在线 RTTT
   └─→ CPU-V1 driver/runtime (F)：把 MCTS 闭环放到 CPU 编排
V1 app (A) ─→ gpu_runtime (C)：工程化 backend + 分类头 + release head
V1 (A/C/F) ─→ V2 (G)：塔 + 元动作 + Eff 通道
容器 QLoRA (B)：独立的 SFT 基线（Qwen3-1.7B）
评测 (H)：横切所有版本
```
